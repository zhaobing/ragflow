# 723-提示词组装逻辑业务流程详解

## 概述

提示词组装是 RAG 流程中的关键环节，位于检索完成后、LLM 生成答案之前。其主要职责是将**检索到的知识**、**系统提示词模板**、**历史对话**、**用户附件**等元素组合成完整的 LLM 输入。

**源码位置**: [api/db/services/dialog_service.py:461-514](../../api/db/services/dialog_service.py#L461-L514)

## 二、核心代码分析

### 2.1 检索结果空响应检查

```python
# dialog_service.py:481-487
retrieval_ts = timer()
if not knowledges and prompt_config.get("empty_response"):
    empty_res = prompt_config["empty_response"]
    yield {"answer": empty_res, "reference": kbinfos, "prompt": "\n\n### Query:\n%s" % " ".join(questions),
           "audio_binary": tts(tts_mdl, empty_res)}
    yield {"answer": prompt_config["empty_response"], "reference": kbinfos}
    return
```

**业务逻辑**:
- 当检索未返回任何知识块时，检查是否配置了 `empty_response`
- 如果配置了空响应，直接返回预设的答案，跳过 LLM 调用
- 节省 LLM 调用成本，提升响应速度

**触发条件**:
1. `not knowledges`: 检索结果为空
2. `prompt_config.get("empty_response")`: 配置了空响应文案

### 2.6 Token 数量控制

```python
# dialog_service.py:504-506
# Token数量控制
used_token_count, msg = message_fit_in(msg, int(max_tokens * 0.95))
assert len(msg) >= 2, f"message_fit_in has bug: {msg}"
```

**message_fit_in 函数详解**:

```python
# rag/prompts/generator.py:61-108
def message_fit_in(msg, max_length=4000):
    """
    确保消息历史不超过max_length限制

    逻辑:
    1. 计算当前token总数
    2. 如果小于限制，直接返回
    3. 优先保留system消息
    4. 如果还不够，截断较长的消息
    """

    def count():
        nonlocal msg
        tks_cnts = []
        for m in msg:
            tks_cnts.append({"role": m["role"], "count": num_tokens_from_string(m["content"])})
        total = 0
        for m in tks_cnts:
            total += m["count"]
        return total

    c = count()
    if c < max_length:
        return c, msg

    # 策略1: 只保留system消息和最后一条消息
    msg_ = [m for m in msg if m["role"] == "system"]
    if len(msg) > 1:
        msg_.append(msg[-1])
    msg = msg_
    c = count()
    if c < max_length:
        return c, msg

    # 策略2: 截断较长的消息
    ll = num_tokens_from_string(msg_[0]["content"])   # system 消息 token 数
    ll2 = num_tokens_from_string(msg_[-1]["content"]) # 最后消息 token 数

    if ll / (ll + ll2) > 0.8:  # system 消息占比 > 80%
        # 截断system消息
        m = msg_[0]["content"]
        m = encoder.decode(encoder.encode(m)[: max_length - ll2])
        msg[0]["content"] = m
        return max_length, msg
    else:
        # 截断用户消息
        m = msg_[-1]["content"]
        m = encoder.decode(encoder.encode(m)[: max_length - ll2])
        msg[-1]["content"] = m
        return max_length, msg
```

**截断策略**:

| 阶段 | 条件 | 操作 |
|------|------|------|
| 1 | 总 token < max_length | 直接返回 |
| 2 | 总 token >= max_length | 保留 system + 最后一条消息 |
| 3a | system 占比 > 80% | 截断 system 消息 |
| 3b | system 占比 <= 80% | 截断用户消息 |

**为何使用 95% 阈值**:
```python
used_token_count, msg = message_fit_in(msg, int(max_tokens * 0.95))
```
- 为 LLM 输出预留 5% 的 token 空间
- 避免输入输出总 token 超过模型上下文窗口

### 2.7 动态调整 max_tokens

```python
# dialog_service.py:508-513
# 提取最终提示词
prompt = msg[0]["content"]

# 动态调整max_tokens
if "max_tokens" in gen_conf:
    gen_conf["max_tokens"] = min(gen_conf["max_tokens"], max_tokens - used_token_count)
```

**计算逻辑**:

```
可用输出 token = min(配置的max_tokens, 模型最大token - 已使用token)

示例:
- 模型最大上下文: 8192 tokens
- 已使用输入: 3000 tokens
- 配置的 max_tokens: 4096 tokens

实际输出上限 = min(4096, 8192 - 3000) = min(4096, 5192) = 4096
```

**gen_conf 示例**:

```python
gen_conf = {
    "temperature": 0.7,
    "top_p": 0.9,
    "max_tokens": 4096,  # 原始配置
    "frequency_penalty": 0.0
}

# 调整后
gen_conf["max_tokens"] = min(4096, 8192 - 3000)  # 假设 used_token_count = 3000
```

## 四、关键依赖方法分析

### 4.1 kb_prompt - 知识组装

**位置**: [rag/prompts/generator.py:111-157](../../rag/prompts/generator.py#L111-L157)

**职责**: 将检索结果格式化为带 ID 的知识块

**核心逻辑**:
```python
def kb_prompt(kbinfos, max_tokens, hash_id=False):
    # 步骤1: 提取内容
    knowledges = [get_value(ck, "content", "content_with_weight") for ck in kbinfos["chunks"]]

    # 步骤2: Token 计数与截断
    for i, c in enumerate(knowledges):
        used_token_count += num_tokens_from_string(c)
        if max_tokens * 0.97 < used_token_count:
            knowledges = knowledges[:i]  # 截断
            break

    # 步骤3: 格式化为树状结构
    for i, ck in enumerate(kbinfos["chunks"][:chunks_num]):
        cnt = "\nID: {}".format(i)
        cnt += draw_node("Title", ck["docnm_kwd"])
        cnt += draw_node("URL", ck.get("url"))
        cnt += "\n└── Content:\n"
        cnt += ck["content"]
        knowledges.append(cnt)

    return knowledges
```

**输出格式**:
```
ID: 0
├── Title: 文档名称
├── URL: https://...
├── 自定义字段1: 值1
└── Content:
文档内容...
```

## 七、性能优化点

### 7.1 Token 预算管理

```
输入预算 = max_tokens * 0.95
输出预算 = max_tokens - used_token_count
```

**设计思路**:
- 95% 阈值: 避免精确计算带来的误差
- 动态调整 max_tokens: 充分利用上下文窗口

### 7.2 消息截断策略

**为何优先保留 system 消息**:
- system 消息包含核心指令和知识
- 历史对话可通过上下文压缩技术优化

**截断时机**:
- system 占比 > 80% → 截断 system
- system 占比 <= 80% → 截断用户消息

## 八、常见问题与调试

### 8.1 提示词过长导致截断

**症状**: 知识内容不完整

**解决方案**:
1. 增加 `max_tokens` 配置
2. 减少 `top_n` 检索数量
3. 调整知识块大小

### 8.2 引用格式不生效

**检查项**:
1. `prompt_config.get("quote")` 是否为 True
2. `kwargs.get("quote")` 是否为 True
3. `knowledges` 是否非空

### 8.3 空响应未触发

**检查项**:
1. 是否配置了 `empty_response`
2. `knowledges` 是否真的为空

## 九、总结

提示词组装是 RAG 系统中的**精密调度环节**，其主要职责包括：

| 职责 | 实现方式 |
|------|----------|
| **知识注入** | 格式化检索结果为树状结构 |
| **上下文管理** | 优先保留关键消息，智能截断 |
| **引用规范** | 动态插入引用指导提示词 |
| **Token 预算** | 95% 安全阈值 + 动态调整 |
| **多模态支持** | 附件内容追加到系统提示词 |

**设计亮点**:
1. **灵活的模板系统**: 支持变量替换和自定义
2. **智能截断策略**: 优先保留关键信息
3. **动态资源分配**: 根据实际使用调整输出预算
4. **可配置的引用**: 支持全局和局部控制
