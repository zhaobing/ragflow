## 核心问题与设计目标

### 为什么需要混合检索？

单一检索方式都存在固有缺陷：

| 检索方式 | 优势 | 劣势 |
|---------|------|------|
| **全文检索** | 精确匹配关键词<br>速度快<br>解释性强 | 无法理解语义<br>关键词缺失导致召回失败<br>同义词问题 |
| **向量检索** | 理解语义意图<br>跨语言能力<br>同义词召回 | 专有名词匹配弱<br>幻觉问题<br>计算成本高 |

**RAGFlow 的设计目标：**

> 通过**混合检索**实现优势互补，用**全文检索保证精确性**，用**向量检索保障语义理解**。

### 全文检索的工作原理

#### 1. 问题分析流程（query.py）

```python
def question(self, txt, tbl="qa", min_match: float = 0.6):
    """
    输入: "RAGFlow 如何实现混合检索？"
    输出:
      - MatchTextExpr: 全文检索表达式
      - keywords: ["ragflow", "实现", "混合", "检索"]
    """
```

**处理流程：**

```
原始问题: "RAGFlow 如何实现混合检索？"
    ↓
① 预处理（中英文分离、全角转半角、繁简转换）
    ↓
② 停用词移除（去除"如何"、"？"等疑问词）
    ↓
③ 分词与术语分割（term_weight.split）
    ↓
④ 权重计算（IDF + NER + 词性）
    ↓
⑤ 同义词扩展（synonym.lookup）
    ↓
⑥ 细粒度分词（fine_grained_tokenize）
    ↓
⑦ 构建 Lucene 查询表达式
```

#### 2. 查询字段权重配置

```python
# query.py:30-38
self.query_fields = [
    "title_tks^10",           # 标题权重 10 倍
    "title_sm_tks^5",         # 标题细粒度分词 5 倍
    "important_kwd^30",       # 关键词权重 30 倍（最高）
    "important_tks^20",       # 关键词分词 20 倍
    "question_tks^20",        # 问题分词 20 倍
    "content_ltks^2",         # 正文分词 2 倍
    "content_sm_ltks",        # 正文细粒度分词 1 倍（默认）
]
```

**设计理念：**
- **优先匹配结构化字段**：标题、关键词权重远高于正文
- **多层级召回**：从高到低逐层匹配，确保不遗漏重要信息

#### 3. 查询表达式生成示例

**输入查询**：`"深度学习算法原理"`

**生成的 Lucene 查询**（简化版）：

```lucene
(
  (深度学习)^0.8 OR
  ("深度 学习")^0.4 OR
  ("深度 学习")~2^0.2          # 近似匹配（间隔2词内）
)^5
OR
(
  (算法)^0.6
  (原理)^0.6
  ("算法 原理"~2)^1.5         # 短语匹配权重更高
)
```

**查询特性**：
- 多层 OR 逻辑：匹配任意术语即可
- 权重分层：原词 > 细粒度分词 > 近似匹配
- 短语提升：`~2` 表示词序相近时加分

#### 4. min_match 参数的作用

```python
# search.py:130
matchText, keywords = self.qryr.question(qst, min_match=0.3)
```

| min_match | 含义 | 使用场景 |
|-----------|------|---------|
| 0.3 (默认) | 至少匹配 30% 的词项 | 首次检索，平衡召回与精度 |
| 0.1 (重试) | 至少匹配 10% 的词项 | 结果为空时放宽限制 |
| 0.6 | 至少匹配 60% 的词项 | 高精度场景 |

**Elasticsearch 转换**：
```python

# 0.3 → "30%"
```

### 向量检索的工作原理

#### 1. 向量生成流程

```python
def get_vector(self, txt, emb_mdl, topk=10, similarity=0.1):
    """
    输入:
      - txt: "深度学习算法原理"
      - emb_mdl: BERT / OpenAI Embedding 模型
      - topk: 返回前 K 个结果
      - similarity: 余弦相似度阈值

    输出:
      - MatchDenseExpr: 向量检索表达式
    """
    # ① 使用 Embedding 模型编码
    qv, _ = emb_mdl.encode_queries(txt)

    # ② 转换为浮点数组
    embedding_data = [get_float(v) for v in qv]

    # ③ 构建向量列名（维度自适应）
    vector_column_name = f"q_{len(embedding_data)}_vec"
    # 例如: "q_1024_vec" (1024维向量)

    # ④ 返回向量匹配表达式
    return MatchDenseExpr(
        vector_column_name,    # 向量列名
        embedding_data,        # 查询向量
        'float',               # 数据类型
        'cosine',              # 余弦相似度
        topk,                  # 返回数量
        {"similarity": similarity}  # 额外参数
    )
```

**关键特性**：
- **维度自适应**：支持任意维度（1024/768/384 等）
- **余弦相似度**：衡量向量夹角的余弦值（范围 [-1, 1]）
- **阈值过滤**：低于 `similarity` 的结果直接丢弃

#### 2. 余弦相似度计算

```python
# 余弦相似度公式
cosine_similarity = (A · B) / (||A|| × ||B||)

# 示例
查询向量 A = [0.5, 0.3, 0.8]
文档向量 B = [0.6, 0.2, 0.9]

相似度 = (0.5×0.6 + 0.3×0.2 + 0.8×0.9) /
         (√(0.5²+0.3²+0.8²) × √(0.6²+0.2²+0.9²))
       = 1.02 / (0.99 × 1.11)
       ≈ 0.93
```

#### 3. similarity 参数的作用

| similarity 值 | 含义 | 召回率 | 精度 |
|---------------|------|--------|------|
| 0.1 | 较高阈值 | 低 | 高 |
| 0.17 | 中等阈值 | 中 | 中 |
| 0.2 | 较低阈值 | 高 | 低 |

**注意**：`similarity` 从 0.1 升至 0.17 是**放宽限制**（阈值越低，过滤越严格）

## 混合检索的融合策略

### 核心代码位置

```python

```

### 融合表达式结构

```python
class FusionExpr:
    def __init__(self, method: str, topn: int, fusion_params: dict):
        self.method = method          # "weighted_sum"
        self.topn = topn              # 返回数量
        self.fusion_params = {        # 融合参数
            "weights": "0.05,0.95"    # [全文权重, 向量权重]
        }
```

### 权重分配详解

| 组件 | 权重 | 计算方式 | 作用 |
|------|------|---------|------|
| **全文检索** | 0.05 (5%) | BM25 分数 × 0.05 | 关键词精确匹配 |
| **向量检索** | 0.95 (95%) | 余弦相似度 × 0.95 | 语义相似度匹配 |
| **最终分数** | 1.0 (100%) | 全文分数 + 向量分数 | 融合排序 |

**计算公式**：

```
最终分数 = (BM25 分数 × 0.05) + (余弦相似度 × 0.95)
```

**示例计算**：

| 文档 | BM25 分数 | 余弦相似度 | 全文加权 | 向量加权 | 最终分数 |
|------|-----------|------------|---------|---------|----------|
| Doc A | 10.0 | 0.85 | 10.0 × 0.05 = 0.5 | 0.85 × 0.95 = 0.81 | **1.31** |
| Doc B | 5.0 | 0.90 | 5.0 × 0.05 = 0.25 | 0.90 × 0.95 = 0.86 | **1.11** |
| Doc C | 15.0 | 0.70 | 15.0 × 0.05 = 0.75 | 0.70 × 0.95 = 0.67 | **1.42** |

**分析**：
- Doc C 虽然语义相似度低，但关键词匹配度高，依然排名第一
- Doc B 语义最相关，但关键词匹配弱，排名靠后
- **体现了"精确性"与"语义性"的平衡**

### 协同工作的优势

#### 1. 互补召回

| 场景 | 全文检索表现 | 向量检索表现 | 混合检索效果 |
|------|-------------|-------------|-------------|
| **精确关键词** | ✅ 优秀 | ❌ 弱 | ✅ 优秀（全文主导） |
| **语义理解** | ❌ 弱 | ✅ 优秀 | ✅ 优秀（向量主导） |
| **专有名词** | ✅ 优秀 | ⚠️ 一般 | ✅ 良好（互补） |
| **同义词查询** | ❌ 弱 | ✅ 优秀 | ✅ 优秀（向量主导） |
| **长尾查询** | ⚠️ 一般 | ✅ 优秀 | ✅ 优秀（向量主导） |

#### 2. 容错能力

**场景 1：关键词缺失**
```
用户查询: "怎么用这个东西实现功能？"
全文检索: 无法匹配（"这个东西"太模糊）
向量检索: ✅ 理解上下文语义
混合检索: ✅ 通过向量分支召回
```

**场景 2：专有名词**
```
用户查询: "RAGFlow 的架构设计"
全文检索: ✅ 精确匹配 "RAGFlow"
向量检索: ⚠️ 专有名词向量表示不准确
混合检索: ✅ 全文分支确保精确召回
```

**场景 3：同义词**
```
用户查询: "车辆保险"
文档内容: "汽车保险"
全文检索: ❌ 无法匹配（不同词）
向量检索: ✅ 语义相近
混合检索: ✅ 向量分支召回
```

#### 3. 分数归一化问题

**挑战**：BM25 分数与余弦相似度量纲不同

## 权重分配的设计哲学

### 为什么是 0.05 : 0.95？

#### 设计考量

1. **语义优先原则**
   - RAG 系统的核心是**理解用户意图**
   - 用户表达方式多样，关键词匹配不足
   - 向量检索能够跨越词汇鸿沟

2. **全文检索的辅助定位**
   - 5% 的权重确保关键词匹配仍有作用
   - 专有名词、精确匹配场景不丢失
   - 提升结果的可解释性

3. **实践经验**
   - 测试表明：95:5 的平衡在大多数场景下表现最优
   - 可通过配置调整以适应特定场景

#### 不同权重比的效果对比

| 全文:向量 | 适用场景 | 优点 | 缺点 |
|-----------|---------|------|------|
| **0.1:0.9** | 语义理解为主的场景 | 语义召回能力强 | 专有名词匹配弱 |
| **0.05:0.95** | RAG 对话（默认） | 平衡语义与精确 | 关键词权重较低 |
| **0.3:0.7** | 专业知识检索 | 关键词匹配增强 | 语义理解下降 |
| **0.5:0.5** | 法律、医疗文档 | 精确性优先 | 语义召回不足 |

## 底层引擎实现对比

### Elasticsearch 实现

**核心代码**：[rag/utils/es_conn.py:186-214](../../../rag/utils/es_conn.py#L186-L214)

```python
# 1. 解析权重
weights = m.fusion_params["weights"]  # "0.05,0.95"
vector_similarity_weight = get_float(weights.split(",")[1])  # 0.95

# 2. 全文检索（BM25）
bqry.must.append(Q("query_string",
    fields=m.fields,
    query=m.matching_text,
    minimum_should_match=minimum_should_match,
    boost=1.0 - vector_similarity_weight  # 0.05
))

# 3. 向量检索（KNN）
s = s.knn(
    m.vector_column_name,
    m.topn,
    m.topn * 2,  # 候选数量 = 2 × topn
    query_vector=list(m.embedding_data),
    filter=bqry.to_dict(),  # 用全文查询作为过滤器
    similarity=similarity
)
```

**特点**：
- 使用 KNN 查询作为外层
- 用全文查询（`bqry`）作为 KNN 的过滤器
- 通过 `boost` 参数调整全文分数权重

**工作流程**：
```
1. KNN 搜索 Top 2K 个向量结果
2. 用全文查询过滤这些结果
3. 加权求和: KNN分数×0.95 + BM25分数×0.05
4. 返回 Top K 结果
```

### Infinity 实现

**核心代码**：[rag/utils/infinity_conn.py:445-490](../../../rag/utils/infinity_conn.py#L445-L490)

```python
# 1. 全文检索
if isinstance(matchExpr, MatchTextExpr):
    builder = builder.match_text(
        fields=",".join(matchExpr.fields),
        matching_text=matchExpr.matching_text,
        topn=matchExpr.topn
    )

# 2. 向量检索
elif isinstance(matchExpr, MatchDenseExpr):
    builder = builder.match_dense(
        vector_column_name=matchExpr.vector_column_name,
        embedding_data=matchExpr.embedding_data,
        distance_type="cosine",
        topn=matchExpr.topn
    )

# 3. 融合（归一化处理）
elif isinstance(matchExpr, FusionExpr):
    if matchExpr.method == "weighted_sum":
        matchExpr.fusion_params["normalize"] = "atan"  # 关键！

builder = builder.fusion(
    matchExpr.method,      # "weighted_sum"
    matchExpr.topn,
    matchExpr.fusion_params  # {"weights": "0.05,0.95", "normalize": "atan"}
)
```

**特点**：
- 使用 `atan` 归一化（解决分数量纲问题）
- 支持 Fusion 原生操作（不是简单的过滤器）
- 分数归一化后再加权求和

**对比总结**：

| 特性 | Elasticsearch | Infinity |
|------|---------------|----------|
| 融合方式 | KNN + filter | 原生 Fusion |
| 归一化 | boost 参数调整 | atan 函数 |
| 性能 | KNN 过滤可能慢 | 融合查询优化 |
| 配置复杂度 | 中等 | 简单 |
| 分数解释性 | 较弱 | 较强 |

## 适用场景与性能分析

### 场景分类

#### 1. **语义理解为主的场景**（推荐 0.05:0.95）

**典型应用**：
- 智能客服对话
- 知识问答系统
- 文档摘要生成

**示例查询**：
```
Q: "我遇到了一个问题，系统总是报错"
A: 即使没有"报错"关键词，向量检索也能理解意图
```

#### 2. **精确匹配为主的场景**（推荐 0.3:0.7）

**典型应用**：
- 法律文档检索
- 医疗文献搜索

### 1. 权重动态调整

根据查询类型动态调整权重：

```python
def get_fusion_weights(query_type):
    """根据查询类型返回权重配置"""
    if query_type == "keyword_heavy":
        return "0.3,0.7"    # 关键词密集
    elif query_type == "semantic_heavy":
        return "0.02,0.98"  # 语义为主
    else:
        return "0.05,0.95"  # 默认
```

### 2. 两阶段检索架构

**架构设计**：
```
第一阶段（召回）：
  - 纯向量检索 Top 2000
  - 低阈值（similarity=0.15）

第二阶段（重排序）：
  - 混合检索 Top 2000
  - 最终返回 Top 100
```

**优势**：
- 减少混合检索的计算量
- 保持召回率的同时提升速度

### 3. 缓存优化

**策略**：
- 向量检索结果缓存（TTL=1小时）
- 全文检索结果缓存（TTL=10分钟）
- 热点查询预计算

- 自动分区，无需手动配置

## 总结

### 核心要点

1. **混合检索的本质**：通过加权融合实现全文检索与向量检索的优势互补

2. **权重分配哲学**：
   - 95% 向量：保障语义理解能力
   - 5% 全文：确保关键词精确匹配

3. **协同工作机制**：
   - 全文检索：基于倒排索引，BM25 打分
   - 向量检索：基于 Embedding，余弦相似度
   - 融合策略：加权求和 + 归一化处理

4. **底层实现差异**：
   - Elasticsearch：KNN + filter 模式
   - Infinity：原生 Fusion + atan 归一化

5. **适用场景**：
   - RAG 对话：0.05:0.95（默认）
   - 专业知识检索：0.3:0.7
   - 专有名词场景：0.2:0.8

### 设计启示

RAGFlow 的混合检索设计体现了以下原则：

- **语义优先**：AI 系统的核心是理解意图
- **精确补充**：关键词匹配作为兜底保障
- **可配置性**：权重、阈值均可根据场景调整
- **性能平衡**：在召回率、精度、延迟之间找平衡
