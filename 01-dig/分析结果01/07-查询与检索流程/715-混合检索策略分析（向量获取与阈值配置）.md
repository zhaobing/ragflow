## 二、向量检索的向量获取与阈值配置

### 2.1 get_vector() 方法详解

**文件位置**: [rag/nlp/search.py:53-69](../../../rag/nlp/search.py#L53-L69)

#### 2.1.1 方法签名与实现

```python
def get_vector(self, txt, emb_mdl, topk=10, similarity=0.1):
    """
    将查询文本转换为向量检索表达式

    参数:
        txt: 查询文本，如 "深度学习算法原理"
        emb_mdl: Embedding模型实例（BERT/OpenAI等）
        topk: 返回前K个结果，默认10
        similarity: 余弦相似度阈值，默认0.1

    返回:
        MatchDenseExpr: 向量检索表达式对象
    """

    # ① 使用嵌入模型编码查询
    qv, _ = emb_mdl.encode_queries(txt)
    shape = np.array(qv).shape
    if len(shape) > 1:
        raise Exception(
            f"Dealer.get_vector returned array's shape {shape} doesn't match expectation(exact one dimension).")

    # ② 转换为浮点数组
    embedding_data = [get_float(v) for v in qv]

    # ③ 构建向量列名 (维度自适应)
    vector_column_name = f"q_{len(embedding_data)}_vec"
    # 例如: "q_1024_vec" 表示1024维向量列

    # ④ 返回密集向量匹配表达式（余弦相似度）
    return MatchDenseExpr(
        vector_column_name,    # 向量列名
        embedding_data,        # 向量数据
        'float',              # 数据类型
        'cosine',             # 相似度算法：余弦相似度
        topk,                 # 返回数量
        {"similarity": similarity}  # 额外参数：阈值
    )
```

#### 2.1.2 关键步骤解析

| 步骤 | 输入 | 输出 | 说明 |
|------|------|------|------|
| **① Embedding编码** | "深度学习算法" | [0.23, -0.45, ..., 0.67] | 使用BERT等模型将文本转换为高维向量 |
| **② 类型转换** | numpy数组 | [0.23, -0.45, ..., 0.67] (float) | 确保向量数据为浮点类型 |
| **③ 列名构建** | 1024维 | "q_1024_vec" | 自适应向量维度，动态生成列名 |
| **④ 表达式封装** | 向量+参数 | MatchDenseExpr | 封装为统一的检索表达式对象 |

#### 2.1.3 余弦相似度算法

**公式**：
```
cosine_similarity = (A · B) / (||A|| × ||B||)
```

**特点**：
- **范围**: [-1, 1]，但Embedding向量通常在 [0, 1] 之间
- **优点**: 不受向量长度影响，只关注方向（语义）
- **应用**: 适合语义相似度计算

## 三、FusionExpr 权重分配机制（5% + 95%）

### 3.1 FusionExpr 类定义

**文件位置**: [rag/utils/doc_store_conn.py:123-127](../../../rag/utils/doc_store_conn.py#L123-L127)

```python
class FusionExpr(ABC):
    """融合表达式：用于混合检索的结果融合"""
    def __init__(self, method: str, topn: int, fusion_params: dict | None = None):
        self.method = method          # 融合方法："weighted_sum"
        self.topn = topn              # 返回结果数量
        self.fusion_params = fusion_params  # 融合参数
```

### 3.2 权重配置详解

#### 3.2.1 权重分配

```python
fusionExpr = FusionExpr("weighted_sum", topk, {"weights": "0.05,0.95"})
```

| 组件 | 权重值 | 百分比 | 作用 |
|------|--------|--------|------|
| **全文检索 (BM25)** | 0.05 | 5% | 关键词精确匹配 |
| **向量检索 (Embedding)** | 0.95 | 95% | 语义相似度匹配 |

#### 3.2.2 融合计算公式

**最终分数计算**：
```
final_score = (bm25_score × 0.05) + (cosine_similarity × 0.95)
```

**计算示例**：

| 文档 | BM25分数 | 余弦相似度 | 全文加权 | 向量加权 | **最终分数** | 排名 |
|------|----------|-----------|---------|---------|------------|------|
| Doc A | 10.0 | 0.85 | 10.0 × 0.05 = 0.50 | 0.85 × 0.95 = 0.81 | **1.31** | 🥉 3 |
| Doc B | 5.0 | 0.90 | 5.0 × 0.05 = 0.25 | 0.90 × 0.95 = 0.86 | **1.11** | 4 |
| Doc C | 15.0 | 0.70 | 15.0 × 0.05 = 0.75 | 0.70 × 0.95 = 0.67 | **1.42** | 🥇 1 |
| Doc D | 8.0 | 0.82 | 8.0 × 0.05 = 0.40 | 0.82 × 0.95 = 0.78 | **1.18** | 🥈 2 |

**关键发现**：
- Doc C 虽然余弦相似度最低（0.70），但BM25分数高（15.0），综合排名**第一**
- Doc B 余弦相似度最高（0.90），但BM25分数低（5.0），综合排名**第四**
- **向量检索主导排序**，全文检索起到微调作用

### 3.3 为什么向量检索权重设置为 95%？

#### 3.3.1 设计理念

1. **语义优先原则**
   - RAG场景更关注语义相关性，而非关键词字面匹配
   - 用户问题可能与文档用词不同，但意思相近

2. **Embedding模型优势**
   - 现代Embedding模型（如BGE, OpenAI）已具备很强的语义理解能力
   - 余弦相似度能准确衡量语义相关性

3. **全文检索辅助定位**
   - 5%权重确保关键词完全匹配的文档不被完全忽略
   - 专有名词、实体等需要精确匹配的场景仍能受益

#### 3.3.2 适用场景

**适合 5:95 权重的场景**：

| 场景 | 特点 | 示例 |
|------|------|------|
| **语义问答** | 关注意思而非字面 | "如何减肥" → 匹配"减重方法" |
| **概念查询** | 同义词、近义词 | "AI模型" → 匹配"神经网络" |
| **长尾问题** | 表述方式多样 | 用户口语化表达 |

**不适合的场景**：

| 场景 | 建议权重 | 原因 |
|------|----------|------|
| **精确实体查询** | 30:70 | 需要"苹果公司"而非"苹果"水果 |
| **代码检索** | 50:50 | 关键词精确匹配更重要 |
| **法律文档** | 40:60 | 法条需要精确引用 |

#### 3.3.3 权重调优建议

```python
# 高语义场景：保持 95% 向量权重
{"weights": "0.05,0.95"}  # 问答、总结、解释

# 平衡场景：降低向量权重
{"weights": "0.15,0.85"}  # 混合查询

# 关键词场景：提高全文权重
{"weights": "0.30,0.70"}  # 精确匹配、实体查询

# 极端场景：完全依赖向量
{"weights": "0.00,1.00"}  # 纯语义检索（不推荐）
```

### 4.2 Elasticsearch 中的 weighted_sum 实现

**文件位置**: [rag/utils/es_conn.py:183-214](../../../rag/utils/es_conn.py#L183-L214)

#### 4.2.1 核心实现

```python
vector_similarity_weight = 0.5  # 默认值

# ① 解析权重
for m in matchExprs:
    if isinstance(m, FusionExpr) and m.method == "weighted_sum":
        if "weights" in m.fusion_params:
            weights = m.fusion_params["weights"]
            vector_similarity_weight = get_float(weights.split(",")[1])
            # "0.05,0.95" → 提取第二个值 0.95

# ② 全文检索部分
for m in matchExprs:
    if isinstance(m, MatchTextExpr):
        minimum_should_match = m.extra_options.get("minimum_should_match", 0.0)
        bqry.must.append(
            Q("query_string",
              fields=m.fields,
              type="best_fields",
              query=m.matching_text,
              minimum_should_match=minimum_should_match,
              boost=1  # 基础权重
            )
        )
        bqry.boost = 1.0 - vector_similarity_weight  # 🎯 应用权重 0.05

# ③ 向量检索部分
elif isinstance(m, MatchDenseExpr):
    similarity = m.extra_options.get("similarity", 0.0)
    s = s.knn(
        m.vector_column_name,
        m.topn,
        m.topn * 2,
        query_vector=list(m.embedding_data),
        filter=bqry.to_dict(),
        similarity=similarity,
    )
```

#### 4.2.2 Elasticsearch 的混合检索机制

**工作原理**：

```
查询: "机器学习算法"
    ↓
┌─────────────────────────────────────┐
│  ① 全文检索 (BM25)                  │
│  - 倒排索引匹配 "机器" "学习" "算法"  │
│  - 计算BM25分数: score_bm25          │
│  - 应用boost: score_bm25 × 0.05     │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  ② 向量检索 (KNN)                   │
│  - 查询向量: [0.23, -0.45, ...]      │
│  - 计算余弦相似度: score_cosine     │
│  - 应用权重: score_cosine × 0.95    │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  ③ 融合打分                          │
│  final_score = bm25 + cosine        │
└─────────────────────────────────────┘
    ↓
排序返回
```

### 4.3 Infinity 中的 weighted_sum 实现

**文件位置**: [rag/utils/infinity_conn.py:446-490](../../../rag/utils/infinity_conn.py#L446-L490)

#### 4.3.1 核心实现

```python
# ① 处理融合表达式
if isinstance(matchExpr, FusionExpr):
    if matchExpr.method == "weighted_sum":
        # 🎯 添加归一化参数：避免分数为0
        matchExpr.fusion_params["normalize"] = "atan"

# ② 应用融合
builder = builder.fusion(
    matchExpr.method,         # "weighted_sum"
    matchExpr.topn,           # 返回数量
    matchExpr.fusion_params   # {"weights": "0.05,0.95", "normalize": "atan"}
)
```

#### 4.3.2 归一化参数的作用

**normalize: atan 的意义**：

| 归一化方式 | 公式 | 特点 | Infinity 默认 |
|-----------|------|------|--------------|
| **minmax** | (x - min) / (max - min) | 线性归一化 | ✅ 默认，但尾部文档分数为0 |
| **atan** | atan(x) × (2/π) | 非线性归一化 | ✅ RAGFlow使用，避免0分 |

**为什么使用 atan**：
- **避免0分**: minmax归一化会导致排名靠后的文档分数为0
- **平滑分布**: atan函数提供更平滑的分数分布
- **稳定排序**: 即使文档分数差异大，也能保持合理排序

**atan归一化效果**：
```
原始分数: [0.1, 0.5, 1.0, 2.0, 5.0]
minmax:   [0.00, 0.08, 0.18, 0.39, 1.00]  → 最小值可能为0
atan:     [0.06, 0.29, 0.50, 0.67, 0.86]  → 所有值都有意义
```

## 五、混合检索的优势互补策略

### 5.1 全文检索 vs 向量检索

| 维度 | 全文检索 (BM25) | 向量检索 (Embedding) |
|------|----------------|---------------------|
| **索引方式** | 倒排索引（关键词→文档） | 向量索引（高维空间） |
| **匹配方式** | 字面匹配（精确） | 语义匹配（模糊） |
| **优势** | 专有名词、实体、精确短语 | 同义词、语义相似、改写 |
| **劣势** | 无法理解语义，依赖关键词 | 可能忽略精确匹配需求 |
| **典型场景** | 代码搜索、法律条文 | 问答、总结、解释 |
| **计算成本** | 低（O(1)查找） | 高（O(n)向量运算） |
| **存储需求** | 小（关键词索引） | 大（向量矩阵） |

### 5.2 混合检索的协同效果

#### 5.2.1 场景示例

**查询**: "如何降低体重"

**全文检索召回**:
- ❌ "减肥方法指南" → BM25分数高（关键词"减肥"）
- ❌ "体重管理方案" → BM25分数低（无"减肥"关键词）
- ✅ "降低体重的10个技巧" → BM25分数高（完全匹配）

**向量检索召回**:
- ✅ "减肥方法指南" → 余弦相似度 0.92（语义相近）
- ✅ "体重管理方案" → 余弦相似度 0.88（语义相近）
- ✅ "减脂饮食计划" → 余弦相似度 0.85（语义相近）

**混合检索融合**:
| 文档 | BM25×0.05 | Cosine×0.95 | 最终分数 | 排名 |
|------|----------|-------------|---------|------|
| "减肥方法指南" | 0.40 | 0.87 | **1.27** | 🥇 1 |
| "体重管理方案" | 0.10 | 0.84 | **0.94** | 🥈 2 |
| "降低体重的10个技巧" | 0.50 | 0.72 | **1.22** | 🥉 3 |

**结论**：
- 全文检索确保精确匹配
- 向量检索扩展语义覆盖
- 融合机制综合两者优势

#### 5.2.2 互补策略的体现

1. **召回互补**
   - 全文: 关键词完全匹配的文档
   - 向量: 语义相关但用词不同的文档
   - 结果: 提高召回率，减少遗漏

2. **排序互补**
   - 全文: 提升关键词精确匹配文档的权重
   - 向量: 提升语义相关文档的权重
   - 结果: 更符合用户期望的排序

3. **鲁棒性互补**
   - 全文: 处理专有名词、代码等
   - 向量: 处理同义词、改写等
   - 结果: 适应多种查询类型

### 5.3 权重为 5:95 的合理性分析

#### 5.3.1 优势

| 优势 | 说明 |
|------|------|
| **语义优先** | RAG场景更关注语义理解 |
| **泛化能力强** | 能应对用户问题的多种表达方式 |
| **减少关键词依赖** | 避免用户必须使用特定关键词 |
| **与现代模型契合** | 充分利用Embedding模型能力 |

#### 5.3.2 潜在问题

| 问题 | 场景 | 影响 | 解决方案 |
|------|------|------|---------|
| **专有名词召回不足** | 查询"Apple公司" | 可能召回水果相关文档 | 调整权重至 15:85 |
| **精确匹配被忽略** | 查询代码函数名 | 可能召回语义相似但不相关的文档 | 提高全文权重 |
| **长尾关键词失效** | 查询特定型号"RX 7900 XT" | 向量模型可能不理解专业术语 | 添加关键词加权 |

#### 5.3.3 何时需要调整权重

**提高向量权重（>95%）**:
- ❌ 不推荐：完全忽略全文检索会失去精确匹配能力
- ✅ 例外：纯语义搜索场景（如概念解释、同义查询）

**降低向量权重（<95%）**:
- ✅ **实体查询**: "Apple公司"需要精确匹配
- ✅ **代码搜索**: 函数名、变量名需要字面匹配
- ✅ **法律条文**: 法条编号需要精确引用
- ✅ **技术文档**: 型号、规格需要精确匹配

**调整建议**：
```python
# 实体查询
{"weights": "0.30,0.70"}  # 全文:向量 = 30:70

# 代码搜索
{"weights": "0.50,0.50"}  # 全文:向量 = 50:50

# 法律文档
{"weights": "0.40,0.60"}  # 全文:向量 = 40:60
```

## 六、检索冲突处理机制

### 6.1 冲突场景分析

**场景**: 全文检索召回但向量检索过滤掉

**示例**:
- 查询: "机器学习算法"
- 文档: "机器学习基础教程"（包含关键词，但语义相关性低）

**检索过程**:
```
全文检索: BM25分数 = 12.0 → 召回 ✅
向量检索: 余弦相似度 = 0.08 → 被过滤（< 0.1阈值）❌

融合结果:
  如果没有相似度过滤:
    最终分数 = 12.0 × 0.05 + 0.08 × 0.95 = 0.60 + 0.076 = 0.676

  如果有相似度过滤（similarity=0.1）:
    向量检索不召回该文档 → 全文检索也不生效
```

### 6.2 Elasticsearch 的处理机制

**KNN查询的filter机制** ([rag/utils/es_conn.py:208-214](../../../rag/utils/es_conn.py#L208-L214))：

```python
s = s.knn(
    m.vector_column_name,
    m.topn,
    m.topn * 2,
    query_vector=list(m.embedding_data),
    filter=bqry.to_dict(),  # 🎯 全文检索作为filter，不作为独立查询
    similarity=similarity,
)
```

**工作原理**：
1. **KNN检索**: 首先进行向量检索，得到候选集合
2. **Filter过滤**: 然后应用全文检索条件过滤候选结果
3. **融合打分**: 最后按照权重计算最终分数

**结果**：
- 如果文档不满足向量相似度阈值，直接被过滤
- 全文检索的BM25分数不会"拯救"低相似度文档

### 6.3 消除冲突的策略

#### 6.3.1 降低相似度阈值

```python
# 放宽向量检索的限制
{"similarity": 0.05}  # 从 0.1 降至 0.05
```

**效果**: 更多文档通过向量检索，全文检索有机会发挥作用

#### 6.3.2 调整权重分配

```python
# 提高全文检索权重
{"weights": "0.15,0.85"}  # 从 5:95 调整为 15:85
```

**效果**: 全文检索对最终分数的影响增大

#### 6.3.3 使用独立的重排序机制

RAGFlow 的解决方案 ([rag/nlp/search.py:159-171](../../../rag/nlp/search.py#L159-L171))：

```python
# 结果为空重试
if total == 0:
    # 降低匹配要求重试
    matchText, _ = self.qryr.question(qst, min_match=0.1)
    matchDense.extra_options["similarity"] = 0.17  # 放宽限制
    res = self.dataStore.search(src, highlightFields, filters,
                                [matchText, matchDense, fusionExpr],
                                orderBy, offset, limit, idx_names, kb_ids,
                                rank_feature=rank_feature)
```

**策略**: 首次检索为空时，放宽相似度阈值重试

## 七、总结与建议

### 7.1 核心要点

1. **向量获取流程**
   - Embedding模型编码 → 浮点数组 → MatchDenseExpr封装
   - 余弦相似度算法，默认阈值0.1

2. **权重分配机制**
   - 5%全文 + 95%向量 = 100%融合分数
   - 向量检索主导排序，全文检索辅助微调

3. **混合检索逻辑**
   - 固定组装顺序：[全文, 向量, 融合]
   - ES使用KNN+filter，Infinity使用fusion+atan归一化

4. **协同优势**
   - 全文: 精确匹配，处理专有名词
   - 向量: 语义匹配，处理同义改写
   - 融合: 综合两者，提升整体效果

### 7.2 调优建议

| 场景 | similarity | weights (全文:向量) | 说明 |
|------|-----------|---------------------|------|
| **标准RAG** | 0.1 | 5:95 | 默认配置，适合大多数场景 |
| **实体查询** | 0.1 | 30:70 | 提高全文权重，强调精确匹配 |
| **代码搜索** | 0.05 | 50:50 | 平衡关键词和语义 |
| **高召回** | 0.05 | 5:95 | 降低阈值，提升召回率 |
| **高精确** | 0.2 | 10:90 | 提高阈值，减少噪声 |

### 7.3 后续研究方向

1. **动态权重调整**
   - 根据查询类型自动调整权重
   - 实体查询提高全文权重，概念查询提高向量权重

2. **自适应阈值**
   - 根据检索结果数量动态调整similarity
   - 结果过多提高阈值，结果过少降低阈值

3. **多轮检索优化**
   - 首轮使用高阈值快速召回
   - 次轮使用低阈值补充召回

4. **A/B测试框架**
   - 对比不同权重配置的效果
   - 基于用户反馈优化参数
