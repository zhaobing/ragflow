# Word完整调用链路梳理

## 概述

## 2. 关键组件职责

### 2.1 API层 (document_app.py)

| 职责 | 说明 |
|------|------|
| 请求接收 | 接收POST /upload请求 |
| 参数验证 | 验证kb_id、文件格式 |
| 权限检查 | 检查用户对知识库的访问权限 |
| 响应返回 | 返回上传成功的文档列表 |

### 2.2 服务层 (file_service.py)

| 职责 | 说明 |
|------|------|
| 文件上传 | 上传文件到MinIO |
| 元数据创建 | 创建Document记录 |
| 文件夹管理 | 管理知识库文件结构 |
| 缩略图生成 | 生成文档缩略图 |

### 2.3 任务队列 (Redis)

| 职责 | 说明 |
|------|------|
| 任务队列 | 存储待处理的文档任务 |
| 消费组 | 支持多消费者并发处理 |
| 消息确认 | ACK机制确保任务不丢失 |

### 2.4 任务执行层 (task_executor.py)

| 职责 | 说明 |
|------|------|
| 任务消费 | 从Redis队列获取任务 |
| 模型绑定 | 绑定嵌入模型和LLM |
| Chunk生成 | 调用解析器生成chunks |
| 向量化 | 生成文本向量 |
| 数据入库 | 将chunks插入存储引擎 |

### 2.5 解析层 (naive.py)

| 职责 | 说明 |
|------|------|
| Word解析 | 解析docx文件结构 |
| 图片提取 | 提取文档中的图片 |
| 表格解析 | 解析表格内容 |
| 文本切片 | 将文本分块 |
| 分词处理 | 生成粗粒度和细粒度分词 |

## 3. 数据流转

### 3.1 原始文件

```
Word文档 (.docx)
    ↓
MinIO存储
    bucket: kb_id
    location: filename
```

### 3.2 解析阶段

```
sections: [(text, image, style), ...]
    ↓
tables: [((None, html), position), ...]
```

### 3.3 切片阶段

```
chunks: [
    {
        "content_with_weight": "文本内容",
        "content_ltks": "粗粒度分词",
        "content_sm_ltks": "细粒度分词",
        "docnm_kwd": "文档名",
        "image": <PIL.Image>,
        ...
    },
    ...
]
```

### 3.4 向量化阶段

```
chunks: [
    {
        ...原有字段,
        "q_768_vec": [0.1, 0.2, ...],  # 添加向量字段
    },
    ...
]
```

### 3.5 持久化阶段

```
Elasticsearch/Infinity
    index: {tenant_id}
    type: chunk
    document: {
        "id": "chunk_id",
        "doc_id": "doc_id",
        "kb_id": "kb_id",
        "content_with_weight": "...",
        "q_768_vec": [...],
        ...
    }
```

## 4. 关键配置参数

| 参数 | 位置 | 默认值 | 说明 |
|------|------|--------|------|
| `DOC_MAXIMUM_SIZE` | settings | - | 最大文件大小 |
| `EMBEDDING_BATCH_SIZE` | settings | 32 | 向量化批量大小 |
| `DOC_BULK_SIZE` | settings | 64 | 存储插入批量大小 |
| `chunk_token_num` | parser_config | 128 | 切片token数 |
| `filename_embd_weight` | parser_config | 0.1 | 标题向量权重 |
| `analyze_hyperlink` | parser_config | False | 是否分析超链接 |

## 5. 错误处理机制

### 5.1 任务重试

```python
# 最多重试3次
if docs[0]["retry_count"] >= 3:
    msg = "ERROR: Task is abandoned after 3 times attempts."
    prog = -1
    return None
```

### 5.2 任务取消

```python
task_canceled = has_canceled(task_id)
if task_canceled:
    progress_callback(-1, msg="Task has been canceled.")
    return False
```

### 5.3 异常捕获

```python
try:
    # 处理逻辑
except TaskCanceledException:
    raise
except Exception as e:
    progress_callback(-1, f"Internal server error: {str(e)}")
    logging.exception("...")
    raise
```

## 6. 性能优化点

| 优化点 | 实现方式 | 位置 |
|--------|----------|------|
| 批量向量化 | EMBEDDING_BATCH_SIZE控制 | embedding() |
| 批量插入 | DOC_BULK_SIZE控制 | insert_es() |
| 标题向量复用 | np.tile广播 | embedding() |
| 异步处理 | asyncio.to_thread | build_chunks() |
| 连接复用 | Session复用 | extract_html() |
| 并发控制 | chunk_limiter, embed_limiter | 全局 |

## 7. 总结

Word文档从上传到入库的完整流程涉及多个层级：

1. **API层**: 接收请求，验证权限
2. **服务层**: 文件存储，元数据创建
3. **队列层**: 任务分发，负载均衡
4. **执行层**: 文档解析，向量化，入库
5. **存储层**: Elasticsearch/Infinity索引

**关键特性**:
- 异步处理架构
- 任务队列解耦
- 批量操作优化
- 完善的错误处理
- 实时进度反馈
