逆向匹配（Reverse Matching）示例
1. 核心概念
正向匹配 vs 逆向匹配：

# 正向匹配 (_max_forward): 从左到右扫描
输入: "南京市长江大桥"
扫描: "南" → "南京" → "南京市" → "南京市长" (不匹配) → 回退到 "南京市"

# 逆向匹配 (_max_backward): 从右到左扫描
输入: "南京市长江大桥"
扫描: "桥" → "大桥" → "长江大桥" (匹配)

3. 为什么需要双向索引？

# key_() - 正向索引: 用于正向匹配
def key_(self, line):
    return str(line.lower().encode("utf-8"))[2:-1]
    # "南京市" → b'\xe5\x8d\x97\xe4\xba\xac\xe5\xb8\x82'

# rkey_() - 反向索引: 用于逆向匹配
def rkey_(self, line):
    return str(("DD" + (line[::-1].lower())).encode("utf-8"))[2:-1]
    # "南京市" → "市京南" → b'DD\xe5\xb8\x82\xe4\xba\xac\xe5\x8d\x97'
在逆向匹配中的使用 (line 319):

def _max_backward(self, line):
    s = len(line) - 1  # 从末尾开始
    while s >= 0:
        e = s + 1
        t = line[s:e]  # 截取子串（从右往左）
        
        # 使用 rkey_ 检查反向Trie中是否有以此为前缀的词
        while s > 0 and self.trie_.has_keys_with_prefix(self.rkey_(t)):
            s -= 1
            t = line[s:e]  # 继续向左扩展
4. 经典歧义消解案例
案例1: "南京市长江大桥"

可能的分词方式:
A. ["南京市", "长江大桥"]  ✓ 正确
B. ["南京", "市长", "江大桥"] ✗ 错误
C. ["南京市", "长江", "大桥"] ✗ 较差

正向匹配: → A
逆向匹配: → A
两者一致 → 结果可靠
案例2: "结婚的和尚未结婚的"

可能的分词方式:
A. ["结婚", "的", "和尚", "未", "结婚", "的"]  ✓ 正确
B. ["结婚", "的", "和", "尚未", "结婚", "的"]  ✗ 错误

正向匹配: 
  "结婚" → "的" → "和尚" (匹配) → B

逆向匹配:
  "的" ← "结婚" ← "未" ← "和尚" (匹配) ← A

差异 → 通过评分算法选择更优方案

6. 反向索引的必要性
问题: 为什么不直接用正向索引做逆向匹配？ 错误示例:

# 假设只有正向索引
def _max_backward_wrong(line):
    s = len(line) - 1
    while s >= 0:
        t = line[s:e]
        # 错误: 用正向索引检查反向字符串
        if self.trie_.has_keys_with_prefix(self.key_(t)):
            # ❌ "长江大桥" 反过来是 "桥江长南"
            #    正向索引查不到以 "桥江长南" 开头的词
            s -= 1
正确做法:

# 使用反向索引
def _max_backward(line):
    s = len(line) - 1
    while s >= 0:
        t = line[s:e]
        # ✓ 检查反向Trie中的前缀
        # "长江大桥" → "桥江长南"
        # 在反向Trie中查找以 "桥江长南" 为前缀的词
        if self.trie_.has_keys_with_prefix(self.rkey_(t)):
            s -= 1
7. 反向Trie的结构

正向Trie (key_):
    根
    ├─ '南' → '京' → '市' → (频率, 词性)
    └─ '长' → '江' → '大' → '桥' → (频率, 词性)

反向Trie (rkey_):
    根
    ├─ '市' → '京' → '南' → 标记=1
    └─ '桥' → '大' → '江' → '长' → 标记=1

逆向匹配时:
"长江大桥" → 反转 → "桥江长南"
在反向Trie中匹配: '桥' → '大' → '江' → '长' ✓ 找到
总结
逆向匹配的核心价值:
消歧: 解决正向匹配的贪心策略导致的错误分词
互补: 正向+逆向互相验证，提高准确率
反向索引: 通过 rkey_() 构建反向Trie，支持高效的前缀匹配
融合: 比较双向结果，选择最优分词方案
这就是为什么在 初始化时 要同时构建正向和反向索引的原因！
